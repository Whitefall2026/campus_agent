# AI 记忆、画像与规划架构（概念区分）

目标：让 AI 能“记住你是谁、你现在怎么样、你处在什么处境”，并据此做
有针对性的规划与建议。四个概念必须严格区分，避免互相污染。

## 1. 结构化事实（Ground Truth）

- 存储：`todos.json`（日程/待办）、课程表、校历。
- 内容：用户实际“发生/安排/承诺”的事件，是画像的证据源，不是画像本身。
- 规则：只有用户确认后的数据才能进入这里。

## 2. 证据层（Evidence）

- 存储：`data/user_evidence.json`。
- 内容：一次性的原始观察：用户说了什么、采纳/拒绝了什么、打了几次“吃力”。
- 特点：只记录、不下结论；带来源和时间；可被删除；有上限。
- 作用：喂给动态画像评估和长期记忆整理。

## 3. 动态画像（Dynamic Profile）

- 存储：`data/user_profile.json` + `data/user_state_history.json`。
- 内容：**现在怎么样**：
  - `energy` 精力（当前可用精力）
  - `task_load` 事务负载（当前并行事务量）
  - `external_pressure` 外部压力（考试/硬线截止等）
  - `situation` 处境（“大创中期”“考试周临近”这类阶段性上下文）
  - `confidence` 置信度
- 特点：短期、会衰减、随事件更新，历史快照用于画曲线。
- 注意：这里不放“你喜欢什么/你是什么样的人”。

## 4. 长期记忆（Long-term Memory）

- 存储：`data/user_memory.json`。
- 内容：**跨会话稳定的事实**，只包含两类：
  - `preference` 偏好：倾向上午深度工作、不喜欢被临时塞事、周末不想排任务；
  - `personality` 性格/风格：直接、不喜欢客套；慢热但承诺可靠；希望建议简洁。
- 特点：慢变量、按重要度保留、需要足够证据或用户明确表达才写入，
  可被用户查看/删除。
- 注意：这里不存“你今天很累”这类瞬时状态。

## 5. AI 综合规划与建议（Planning + Advice）

规划时，AI 一次性拿到四份输入，但分工明确：

| 输入 | 用途 |
|---|---|
| 动态画像 + 处境 | 决定“今天/本周强度上限、该不该减负、保什么” |
| 长期记忆（偏好/性格） | 决定“什么任务放什么时段、语气与建议风格” |
| 精力曲线 + 反馈统计 | 校验具体时段是否合适 |
| 结构化事实（日程/课程/截止） | 硬约束，不可违背 |

AI 输出两类东西：

- `plan`：任务 → 日期/时段（含理由）；
- `advice`：无法塞进日程时怎么办、优先级怎么调、要不要先拆解/顺延、
  以及基于性格的沟通建议。

能量引擎只做一件事：校验 AI 的 plan（空闲、能耗、硬线、风险），
不合法就拒绝并给引擎兜底方案。它不是与 AI 平级的决策者。

## 6. 冷启动

动态画像可以从结构化事实 + 能量引擎数据直接推导
（`derive_from_planner`），不需要先聊够多少条：
待办数量 → 负载；硬线截止 → 压力；精力系数/反馈 → 精力；日程密度 → 处境。
对话只是补充，不是门槛。
